# Known bugs

Open bugs only, one entry each: symptom, cause, suggested fix. The commit that fixes a bug deletes its entry.

- **`lsp` test `a_cancelled_pull_is_answered_with_request_cancelled` flakes under load** (`crates/lsp/tests/responsiveness.rs`, `#[ignore]` until fixed). Symptom: fails when other builds load the machine, passes alone (about 2,800 runs alone did not reproduce it). Cause: not found. The test assumes the server has read both `$/cancelRequest` notifications before it answers the `format` sent after them; under load that ordering may not hold. Suggested fix: confirm by logging the order the loop reads messages in, then make the test wait for an observable point (or make the loop drain pending notifications before answering a request), and remove the `#[ignore]`.
- **JS `no-undef` (off)**: it knows only ES builtins (as ESLint without `env`), so `console`, `window`, `expect`, `btoa` are reported (108 per 10k lines on the corpus). Fix: an `environments` option (`browser`, `node`, `test`) with globals data files, default on for all three; the browser set alone is about 700 names, so it is a data task of its own.
- **Dockerfile `ADD ${REPO}#${REF} /` is a syntax error** (tree-sitter-containerfile 0.9 does not accept `#` after a variable in an `ADD` source; after the error the next `FROM` can be lost, so `copy-from-unknown-stage` and `copy-from-own-stage`, kept on, can then report falsely). Fix: vendor the grammar as a fork ([development/grammar-forks.md](development/grammar-forks.md)) and accept `#` in unquoted arguments; not done because it needs the whole grammar vendored and regenerated with the pinned `tree-sitter` CLI.
- **First active rule costs about 5M instructions per bench input in protobuf** (lint 532,677 with no rule on, 5,477,200 with `enum-first-value-zero`): engine setup (rule compilation, traversal dispatch tables), not the rule. Look at it when lint startup is tuned.
- **Python scope pass, rare differences from ruff** (found on ruff's, black's and CPython's own test files, none in the parity corpus): `F823` is reported on a `match match:` subject and on a read of a module name bound by a walrus when ruff is silent (`tests/data/cases/pattern_matching_generic.py`, `pep_572_remove_parens.py` of black); `F811` on the repeated parenthesized targets of `with a as ((x), (y))` (`preview_unpacking_parens.py`) is not reported. Cause: ruff's rules for which binding a later rebinding shadows are not fully reproduced. Fix: probe ruff on a reduced file and adjust `Model::undefined_local` and `Model::redefinition`.
- **Vue: a valueless shorthand directive swallows the next shorthand attribute** (`<input :disabled @click="go">` parses as one `Attribute` `:disabled @click="go"`; a directive that starts with `v-` is fine). Cause: tree-sitter-vue's `directive_attribute` repeats `(':' | '.' | '@' | '#') value` across whitespace. Effect: the rules on attributes (`valid-v-on`, `no-duplicate-keys`, ...) see one attribute and miss the second. Fix: make the repeat immediate in `grammars/tree-sitter-vue/grammar.js` and regenerate `src/` with the pinned `tree-sitter` CLI ([development/grammar-forks.md](development/grammar-forks.md)).
- **Java: rezel 0.0.0 fails on two kinds of valid input** (2 of 5,337 corpus files; the file is a parse error and stays as written): a text block containing an escaped `\"""` (google-java-format's `FormatterTest.java` panics in `rezel-lr` on `is_boundary`; the adapter catches it), and a chain of about 300 or more calls (`b.add("x").add("y")...`, Error Prone's `WellKnownMutability.java`; 200 parse, 400 give a recovery node per call). Fix upstream or patch the pinned version; `conformance` names both files.
