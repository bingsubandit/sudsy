# CLI (`crates/cli`)

| Command | What it does | Exit |
|---|---|---|
| `format [--check] [paths]` | Format files; `--check` reports without writing | 1 if `--check` finds changes |
| `lint [--rule ID,...] [--new[=REV]] [paths]` | Report diagnostics; `--rule` keeps only those rules' findings, `--new` only those the files at git `REV` lack ([below](#only-new-findings)) | 1 on any error-level diagnostic |
| `fix [--unsafe \| --apply ID,...] [paths]` | Apply fixes (loop), then format; `--apply`: [below](#fix-ids) | 1 if errors remain; 2 on an unknown id |
| `check [--rule ID,...] [paths]` | `format --check` + `lint`, for CI; an unformatted file is an error diagnostic `format` at 1:1 | 1 on any error or unformatted file |
| `rules [term] [--language <lang>]` | List rules; an exact rule id explains it (options, presets that enable it, equivalent ids of other tools from the parity catalog); an exact id of another tool (`SA1005`, `truthy`) explains the rule that covers it; other text lists the rules whose id, description or equivalent ids contain it (case-insensitive). `--language` keeps the rules that apply to that language, shared ones included | 0; 2 when nothing matches |
| `config print [file]` | Resolved config with the source of each value | 0 |
| `init [--preset <name>] [--from <tool>]... [--force] [--yes] [--languages a,b] [--vscode] [--ci] [--agents]` | Interactive in a terminal ([below](#init-questions)); without one the starter, or the `--from` migration | 0; 1 when cancelled |
| `init --agents` | Add a marked block (`<!-- sudsy:start -->` ... `<!-- sudsy:end -->`: run `sudsy check`, fix with `sudsy fix --unsafe` or `sudsy fix --apply <id>`, explain with `sudsy rules <id>`) to `AGENTS.md`, or to `CLAUDE.md` when only that exists (`AGENTS.md` is created when neither does); a file that has the start marker is left alone. Alone it writes nothing else; with `--preset`, `--from` or `--force` it also does the normal init. Never without the flag (`crates/cli/src/init/agents.rs`) | 0 |
| `init --from <tool> [--force] [--write-editorconfig]` | Write the `sudsy.yaml` equivalent of another tool's config in the working directory ([below](#init---from)) | 0 |
| `lsp` | Language server on stdio ([editor/lsp.md](../editor/lsp.md)) | |
| `debug parse <file>` | Developer: parse a `.cs` file with the worker, check round trip, print the tree | |

- Exit 2 on any command: a file could not be processed (syntax error, unreadable, bad option, worker unavailable, nested deeper than 1,000 brackets, a panic in a parser, formatter or rule) or the config is invalid. Failed files are left alone and the rest are processed. Results are reported in path order.
- `lint`, `fix`, `check`: `--format human|concise|json|sarif|github`, `--analysis fast|standard|deep` and `--new[=REV]` ([below](#only-new-findings)).
  - Human (`crates/cli/src/human.rs`, the form agents read): `path:line:col: severity[rule]: message`, then the source line (`    12 | text`; none for a blank line or the `format` finding), `note:` lines, and per fix `fix (safe): title` or `fix ID (unsafe|suggestion): title` followed by its change: the edited line (`    12 | new text`) when it changes one line, else up to 3 old (`-`) and 3 new (`+`) lines and `... (N more lines)`; lines the edits leave alone are not shown. A line over 160 characters is cut around the finding (40 before it). No colours.
  - Collapse: a human report of more than 100 findings is one line per rule (`severity[rule]: N findings (M with a fix): the first 3 locations, ...`; errors first, then by count) and a last line naming `--rule` and `--format concise`. 100 findings in full are about 300 lines; the collapsed form saved agents 21-38% of input tokens at 127 findings (design/agent-workflows.md, E8). `--rule` never collapses; the other formats never do.
  - Concise: the first line of each finding only.
  - JSON: `{version, summary, diagnostics}` with byte offsets, line/column ranges and fix edits. SARIF 2.1.0: results and rule table, no `fixes`. GitHub: `::error|warning file=,line=,col=,endLine=,endColumn=,title=::message`.
- Discovery (`core-workspace`): `.gitignore` honored also outside a git checkout, hidden directories included, `.git` excluded; explicit file arguments are always kept.
- `format` and `fix` write atomically: a temp file in the same directory, synced, then renamed over the original with its permissions kept. A file given as a symlink is resolved first, so the link stays and its target is rewritten (walks never follow symlinks).
- Diagnostic text and paths are untrusted: control characters (ANSI escapes, newlines) are shown as escapes in the human and github formats.
- A UTF-8 BOM is kept. A file that is not UTF-8 is read as UTF-16 (byte-order mark) or Windows-1252 and written back in that encoding (`provider_api::encoding`); a result with a character the encoding lacks is an error. A UTF-8 file with a NUL byte is refused. A single-byte file is refused as not valid UTF-8 when its bytes could be another encoding (Shift-JIS, GBK): a control byte other than tab, line breaks and form feed, a byte Windows-1252 leaves undefined, or a byte from 0x80 up followed by one of ``@[\]^`{|}~`` (a trail byte). A result that changes a byte from 0x80 up or the one after it (a trimmed no-break space, a recased letter) is refused too. If the semantic model is unavailable (worker crash, refusal), `lint`/`fix`/`check` print one stderr warning per distinct reason and run the other rules.
- `format`, `lint`, `fix` and `check` print one stderr warning per `.editorconfig` line that sets a C# formatting key Sudsy does not follow ([editorconfig.md](editorconfig.md)).
- `mimalloc` is the global allocator (25-40% faster on the format path).
- The JSON Schema is generated by `cargo xtask codegen`, not by the CLI.

## Fix ids
`core_rules::fix_ids`: every unsafe and suggestion fix gets a 6-character id (base 32, 30 bits), an FNV-1a hash of the path as printed, the rule, the trimmed text of the finding's first line, the finding's occurrence among that rule's findings on equal lines, and the fix's index. Nothing is stored: the id stays while that line's text is unchanged (moving or reindenting the line keeps it) and is printed in the human report and as `id` of the fix in JSON. Safe fixes have none (`fix` applies them unasked).
- `fix --apply ID[,ID...]` (case-insensitive; not with `--unsafe`) lints the files of the run, applies exactly the fixes with those ids (suggestions included, no other fix) in one round, then formats only the files that got a fix, and reports what remains. A named fix that overlaps another named one is not applied (a warning; its id after the edit is in the report); a round that would leave the file unparseable is not applied.
- An id no fix has (its line changed, the fix is gone) is an error after the report, with up to 20 current ids as `ID (rule, path:line)`; the other ids are still applied; exit 2.
- `fix --unsafe` stays the accept-all (safe and unsafe); suggestions are applied only by id. Project and directory findings are not part of `fix` (it lints each file alone), so their ids are unknown to `--apply`.

## Only new findings
`--new[=REV]` (`REV` defaults to `HEAD`, so the working tree against the last commit; `--new=origin/main` checks a branch against its base) keeps the findings that the file at `REV` does not have (`crates/cli/src/new.rs`). Nothing is stored: git (`core_workspace::git`: `rev-parse`, `ls-tree`, `diff --name-only`, one `cat-file --batch` for all changed files) gives the files of `REV` and the changed ones; each changed file's old text is linted in memory with the current config, and findings are matched by fingerprint (`core_rules::fingerprint`, also the base of fix ids): the rule, the trimmed text of the finding's first line, its occurrence among that rule's findings on equal lines. A moved or reindented line keeps its findings old; an edited line's findings, and a second equal line's, are new.
- A file unchanged since `REV` has no new finding; a file `REV` does not have (untracked, added, outside the repository) has only new ones. Project and directory findings of a changed file are compared with the file's own findings at `REV`, so they count as new.
- `check`: a changed file's `format` finding is new when the file was formatted at `REV`.
- `fix --new` applies fixes as without it and reports only the new findings that remain.
- Exit code and summary count only new findings; the summary says `new error(s)` and is left out when there is none, so a clean run prints nothing (human and concise) and exits 0.
- Outside a git repository, or with an unknown `REV`: an error before any file is read (exit 2).

## `init` questions
`crates/cli/src/init/`: `world.rs` (the scan and what exists), `ask.rs` (the questions, skipped when a flag answers them), `plan.rs` (`Answers` to files: the one model), `prompt.rs` (`Terminal` with `dialoguer`, `Lines` for `TERM=dumb`, `Defaults` for `--yes`), `editor.rs` and `json_edit.rs` (VS Code and CI files). The agent block is paragraphs, not a list, so the formatter leaves it alone under any indent width.
- Asked only when stdin and stderr are terminals, none of `CI`, `GITHUB_ACTIONS`, `GITLAB_CI`, `TF_BUILD`, `JENKINS_URL`, `BUILDKITE` is set and `--yes` is absent; else the starter or the `--from` migration, as before. `--agents` alone adds only the block. An existing sudsy config stops the run before any question unless `--force`.
- Order: languages (the working directory walked with the project's own walk, ignore files respected, 20,000 files or 2 s; counts shown), one Style question (keep the tools found: their presets and settings are taken over; Sudsy's defaults; choose per language: one question per group of languages that offer the same presets, then which tools' settings to take over), lint level (presets that only set rule levels: likely bugs only, or the ones chosen), `AGENTS.md`/`CLAUDE.md` (existing ones preselected), editor (when `.vscode/` exists; ids from `languages::vscode_languages`, generated from `vscode-languages` of each `lang.yaml`) and CI (when `.github/` or a github.com remote exists), then the summary and one confirm. Files are written only after it.
- Keeping the tools: a language two tools give different style presets is asked ("Style for yaml"); a tool's settings for a language that follows another tool's style are not written and are printed as `not migrated`. A value two tools set differently is asked. A tool's section is written only for languages found (and kept) in the repository.
- Afterwards the files `init` created run through `sudsy fix` (safe fixes and the formatter, with the config just written; a child process of the same binary). Files the user already had are not reformatted; when one of them does not pass `sudsy format --check`, the last line says `next: run `sudsy format`, then `sudsy check``.
- Languages left out are added to `exclude` as globs of their file matchers; a glob that would also catch a file of a language that stays (`*.yml` and the workflows) is not written and a note names the language.
- Files: `sudsy.yaml`; the agent block (appended, once); `.vscode/extensions.json` and `.vscode/settings.json` (entries appended as text when plain JSON, so keys and indentation stay (`json_edit.rs`); a file with comments is left alone and a note says what to add); `.github/workflows/sudsy.yml` (only when absent). A new file is created with `create_new`; a failure while writing names the files already written.
- Esc or Ctrl-C at any question: `cancelled; nothing written`, exit 1 (Ctrl-C: exit 130, the cursor shown again; `ctrlc` handler). `Lines` ends the run when the input ends.
- Looks: `console` honours `NO_COLOR`; items are cut to the terminal width; `TERM=dumb` gets numbered lines.

## `init --from`
`--from yamllint|prettier|biome|eslint|stylelint|stylecop|csharpier|html-validate|htmlhint|html-eslint` reads that tool's config in the working directory and writes `sudsy.yaml`. The report (stdout) lists the presets it extends, every `not migrated: <key> (<reason>)` and notes. An existing `sudsy.yaml`/`sudsy.yml` is replaced only with `--force`. The files are untrusted: read with the 1 MiB cap of Sudsy's own loader, and a parse error names the file (exit 2).

| Tool | Reads | Extends | Maps |
|---|---|---|---|
| `yamllint` | `.yamllint`, `.yamllint.yaml/.yml` | `yaml/yamllint` for `extends: default` or `relaxed` | rule levels and options, indentation, line length, spacing, blank lines, newline settings |
| `prettier` | `.prettierrc`, `.prettierrc.json/.yaml/.yml`, `package.json` `"prettier"`, `.prettierignore` | `json/prettier-compat`, `yaml/prettier-compat` | `printWidth`, `tabWidth`, `useTabs` (not YAML), `endOfLine`, `bracketSpacing` (JSON, YAML, JS), `singleQuote` (YAML, JS `quote_style`, CSS `single_quote`), `objectWrap`; for JS `semi`, `quoteProps`, `trailingComma`, `arrowParens`, `bracketSameLine`, `jsxSingleQuote`; for HTML, Vue and Svelte (`html:`, `vue:`, `svelte:`) `printWidth`, `tabWidth`, `useTabs`, `endOfLine`, `bracketSameLine`, `singleAttributePerLine`, `htmlWhitespaceSensitivity`, `embeddedLanguageFormatting`, `vueIndentScriptAndStyle`, `svelteIndentScriptAndStyle` |
| `biome` | `biome.json`, `biome.jsonc` | `json/biome` | `formatter` and `json.formatter` (the latter wins), `json.parser`, the JSON lint rules, `useSortedKeys` |
| `eslint` (alias `eslint-jsonc`) | `.eslintrc.json/.yaml/.yml`, `.eslintrc`, `package.json` `"eslintConfig"`, `.eslintignore` (top level and `overrides` for `*.json*` and script files) | `js/eslint-recommended` for `eslint:recommended`, `js/typescript-eslint-recommended` for `plugin:@typescript-eslint/recommended` | core rules and `@typescript-eslint/` rules through `docs/ai/parity/eslint.yaml` and `typescript-eslint.yaml` (a rule Sudsy lacks is listed with its catalog status), `globals` as `undefined-variable`'s `globals`, `ignorePatterns` and `.eslintignore` as `exclude`; `jsonc/*` rules with their options and the JSON formatting rules (`indent`, `comma-dangle`, spacing). Plugin rules and shared configs are listed as not migrated. A flat `eslint.config.*` or `.eslintrc.js` is JavaScript: refused with an explanation |
| `stylelint` | `.stylelintrc`, `.stylelintrc.json/.yaml/.yml`, `package.json` `"stylelint"`, `.stylelintignore` | `css/stylelint-recommended` or `-standard` for `stylelint-config-recommended`/`-standard` (also the `-scss`/`-less` variants, with a note that their plugin rules are not included) | rules of `docs/ai/parity/stylelint*.yaml` (`scss/` rules under `scss:`, `less/` under `less:`, the rest under `css:`) with level (`null` off, `severity`, `defaultSeverity`) and the options Sudsy's rule has: list, pattern, maximum, `color-hex-length`, the one string value a rule without options implements (`function-name-case: lower`), `ignore` of `declaration-block-no-duplicate-properties`; `ignoreFiles` and `.stylelintignore` to `exclude`. Other shared configs, `overrides`, negated ignore patterns, other options and a JavaScript config (`stylelint.config.*`, `.stylelintrc.js`) are not migrated |
| `html-validate` | `.htmlvalidate.json` (`.htmlvalidate.js` is refused) | `html/html-validate-recommended` or `-standard` for `html-validate:recommended`/`:standard` | `rules` with level and, for the `*-pattern` rules, a regex `pattern` (a named style such as `kebabcase` is listed); `elements`, `plugins` and `transform` are listed |
| `htmlhint` | `.htmlhintrc` | none | each rule `true` (error) or `false` (off); rules with a value (`id-class-value`) are listed. HTMLHint runs only the listed rules, which a note says |
| `html-eslint` | the legacy ESLint config of `eslint` (top level and `overrides` for `*.html`) | none | `@html-eslint/*` rules with level; a shared config in `extends` is not followed |
| `stylecop` | `stylecop.json`, `.stylecop.json`, `dotnet_diagnostic.SA*.severity` in `.editorconfig` | `csharp/stylecop` | indentation, newline at end of file, do-while, `systemUsingDirectivesFirst`, `elementOrder`; severities of SA ids that map to a Sudsy rule |
| `csharpier` | `.csharpierrc`, `.csharpierrc.json/.yaml/.yml` | `csharp/csharpier-compat` | `printWidth`, `useTabs`, `indentSize`, `endOfLine` |

- Only differences from the extended presets are written.
- The mappings are checked against the parity catalog (`docs/ai/parity/*.yaml`, embedded in the binary). The reason after `not migrated` is the catalog's `gap` or status. In debug builds a mapping whose catalog entry names a different option or rule panics; `tests/fixtures/init/<tool>/` run every mapping through that check and snapshot the result.
- C# tools also print the `.editorconfig` entries under `[*.cs]` that switch off checks Sudsy now does: `dotnet_diagnostic.IDE0055.severity = none` (CSharpier), plus every SA id the catalog marks covered (StyleCop), and a note to set `EnforceCodeStyleInBuild` so `dotnet build` reports the other IDE rules. `--write-editorconfig` appends them to `.editorconfig` (created if missing; once).
