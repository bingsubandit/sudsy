# Documentation site

Public rule reference at https://bingsubandit.github.io/sudsy/, built with Astro Starlight (versions pinned in `site/package.json`; latest version only). Everything outside `getting-started.md` and the two index pages is generated; the rest of `docs/` is for contributors and is not published.

## Build and preview
`scripts/site.sh build` (`npm ci`, generate, `astro build` into `site/dist`), `scripts/site.sh dev` for the dev server (no search index there; the rules index says so), `scripts/site.sh preview` to build and serve the site with search at http://localhost:4321/sudsy/. `scripts/site.sh test` builds, serves `site/dist` with `astro preview` and runs `site/test/smoke.mjs` (Playwright against the installed Edge or Chrome; no browser download): rule search, every filter, query-parameter preselection, the single Rules sidebar entry, a rule page (squiggles, configuration), an upstream-id redirect, the header search, and no console or network errors. Node 24. `scripts/site.sh scale-test [N]` builds with N synthetic rules (default 10 000) from a copy of `rules.json` in the build slot and prints build time and sizes ([performance/numbers.md](../performance/numbers.md)). The site is not part of `scripts/gate.sh`; the `site` workflow builds it.

## Data
`site/scripts/generate.mjs` writes Markdown into `site/src/content/docs/generated/` (git-ignored) before each build:
- `docs/ai/rules/rules.json` (from `cargo xtask codegen`; `SUDSY_RULES_JSON` overrides the path): one page per rule at `/rules/<id>/` with description, languages, category, fix kind, options, upstream equivalents, the fixture example (input with the reported spans as red wavy underlines whose hover text is the rule id, then the fixed output) and one Configuration section (a `sudsy.yaml` snippet with the level and every option at its default, the options table, the presets that enable it and the suppression comment); a rule of several languages has one page. The underlines are the `squiggles="line:column:length,..." tip="..."` meta of a code block, handled by the small Expressive Code plugin in `site/ec.config.mjs`.
- Each upstream id (`SA1005`, `DL3008`) gets `/rules/<id>/` too, as a plain static file in `public/rules/` (git-ignored; a Starlight page would carry 19 KB of layout): a meta refresh and canonical link to the Sudsy rule when one rule matches, a list of links when several do. Not in the search index; rule pages list their upstream ids. Ids with characters outside `A-Za-z0-9_-` are slugified; an id equal to a Sudsy rule id is skipped.
- `docs/ai/parity/site.json` (from `cargo xtask codegen`: the rows of `xtask/full/support.yaml` with their measured shares, speed rows and presets, and every parity catalog with its coverage) via `site/scripts/pages.mjs`: one page per language at `/languages/<id>/` (parity numbers, speed, presets, rule count), one page per compared tool at `/compare/<tool>/` listing every rule and setting of the tool with the Sudsy rule, the coverage and the gap note, and the two indexes `/languages/` and `/compare/`. Rule pages link their languages and upstream tools and show the measured coverage of each tool.
- `crates/lang-*/presets/*.yaml` with the notes column of `docs/ai/formatting/presets.md`: `/reference/presets/`.
- `schemas/sudsy.schema.json`: `/reference/format-options/`.
- A language page lists the presets whose file is in its `crates/lang-<id>/presets/` or whose rules apply to one of its language ids (`discover.rs`), so Vue and Svelte list the `html/` presets that enable their rules.

## Agent docs
`site/scripts/agents.mjs`, called by `generate.mjs`, writes into `public/` (git-ignored): a Markdown twin of every page (`/<slug>.md`, from the same front matter and body, with layout HTML and the editor meta removed and links pointing at twins; the landing page and the rules index, which are a hero and a component, get a short text), `llms.txt` (guide, machine-readable outputs, every language and compared tool page as a link, per the llms.txt convention), `llms-full.txt` (the guide and language pages in one file; rule and tool pages stay out, they are fetched one at a time) and `rules.json` (a copy of `docs/ai/rules/rules.json`). The hand-written `cli.md` documents the commands, the `--format json` shape, `rules.json` and `init --agents`; there is no `rules --json` command, the file is the machine-readable rule list.

## Search engines
Every page carries a canonical URL (Starlight, from `site`/`base` in `config.mjs`), `sitemap-index.xml` (Starlight's sitemap integration; `robots.txt` points to it), and the OpenGraph and Twitter image `og.png` (`assets/logo/og.png`, the logo on a 1200x630 background; copied to `public/` by the generator). `public/google016a7f3076a694ed.html` is the committed Google Search Console verification file; keep it. The `<title>` of rule, language and tool pages is set per page through `head` in the front matter: a rule names its languages and the tools it matches (`no-debugger: JavaScript / TypeScript lint rule, like ESLint no-debugger | Sudsy`), a language names its reference tools, a tool page names the tool. Descriptions are generated too.

## Page check
`generate.mjs` fails the build (and so the `site` workflow) when a rule has no page, a language of a rule has no row in `support.yaml`, or a language row or compared tool has no page. `cargo xtask codegen` fails when a language of the providers or a language name of `bench/speed.json` is in no row of `support.yaml`, since that language would have no page.

Hand-written: `src/content/docs/` (landing, getting started, rules index), `src/components/RuleSearch.astro`, `astro.config.mjs`.

## Search
Starlight's built-in Pagefind search covers every page. The rules index (`/rules/`, `RuleSearch.astro`) queries the same index through Pagefind's JS API (its default UI shows nothing without a search term): a search box, checkbox filters from the `data-pagefind-filter` chips on rule pages (`language`, `category`, `fix` (`none`, `safe`, `suggestion`, `unsafe`), `preset`, `upstream` (tool); several values of one filter match any), and the first 50 hits (sorted by id without a term). `?language=csharp`, `?preset=...` and `?q=...` preselect them. Only pages with a category (rule pages) are listed. A rule for `all` languages matches every language filter. The sidebar lists no rules (Starlight renders it into every page, so it would grow with the square of the rule count); it has one "Rules" entry, the index. The default level is not a filter: levels are configurable.

## Deploy
`.github/workflows/site.yml` builds the site and uploads the Pages artifact. It runs on pull requests and pushes to main that touch the site inputs (`site/**`, `docs/ai/rules/rules.json`, `docs/ai/parity/site.json`, `assets/logo/og.png`, `docs/ai/formatting/presets.md`, the schema, preset files) and fails when `site/dist` exceeds 800 MB (the Pages limit is 1 GB); a push to main also deploys (Settings > Pages > Source is "GitHub Actions"). The VS Code extension's `DOCS_BASE_URL` and diagnostic links switch on after the site is live ([roadmap](../roadmap.md)).
