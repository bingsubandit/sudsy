# Known bugs

Open bugs only, one entry each: symptom, cause, suggested fix. The commit that fixes a bug deletes its entry.

- **`lsp` test `a_cancelled_pull_is_answered_with_request_cancelled` flakes under load** (`crates/lsp/tests/responsiveness.rs`, `#[ignore]` until fixed). Symptom: fails when other builds load the machine, passes alone (about 2,800 runs alone did not reproduce it). Cause: not found. The test assumes the server has read both `$/cancelRequest` notifications before it answers the `format` sent after them; under load that ordering may not hold. Suggested fix: confirm by logging the order the loop reads messages in, then make the test wait for an observable point (or make the loop drain pending notifications before answering a request), and remove the `#[ignore]`.
- **Ruby tree has two nested `Program` nodes** (the root and the one Prism makes): a check registered on `Program` runs twice unless it skips the outer one (`unknown-rule-in-directive` does); the adapter should emit one.
- **JS `undefined-variable` (off)**: it knows only ES builtins (as ESLint without `env`), so `console`, `window`, `expect`, `btoa` are reported (108 per 10k lines on the corpus). Fix: an `environments` option (`browser`, `node`, `test`) with globals data files, default on for all three; the browser set alone is about 700 names, so it is a data task of its own.
- **Dockerfile: `#` after a variable expansion is read as a comment** (`grammars/tree-sitter-containerfile`, the vendored fork of tree-sitter-containerfile 0.9.2): `ADD ${REPO}#${REF} /` (buildx `jaeger-ui-rest/Dockerfile`, line 10) and `ARG X=${V#linux/amd64}` (moby `Dockerfile`, lines 39-43) give the tree an `ERROR` node and the text after the `#` is read as a comment (a `FROM` after it can be lost). The two corpus files where tree-sitter reports an error. Fix: a grammar.js change in the fork (`unquoted_string` or the `expansion` rule must take `#` inside `${...}` and right after `}`), regenerated with `scripts/grammar-regen.sh containerfile`; then check that `tree-sitter parse` reports no error on both files.
- **First active rule costs about 5M instructions per bench input in protobuf** (lint 532,677 with no rule on, 5,477,200 with `enum-first-value-zero`): engine setup (rule compilation, traversal dispatch tables), not the rule. Look at it when lint startup is tuned.
- **Python scope pass, rare differences from ruff** (found on ruff's, black's and CPython's own test files, none in the parity corpus): `F823` is reported on a `match match:` subject and on a read of a module name bound by a walrus when ruff is silent (`tests/data/cases/pattern_matching_generic.py`, `pep_572_remove_parens.py` of black); `F811` on the repeated parenthesized targets of `with a as ((x), (y))` (`preview_unpacking_parens.py`) is not reported. Cause: ruff's rules for which binding a later rebinding shadows are not fully reproduced. Fix: probe ruff on a reduced file and adjust `Model::undefined_local` and `Model::redefinition`.
- **Python `invalid-syntax` covers four of ruff's semantic syntax errors** (duplicate parameter, repeated keyword argument, `nonlocal` at module level, `await` outside an async function). Not reported: `async for` / `async with` outside async functions, rebound comprehension variables, duplicate type parameters, `match` pattern errors, `__debug__` writes, name used before `global` / `nonlocal`, starred assignment targets and expressions in invalid places. None is in ruff's default set as its own rule; the corpus has no finding of them. Fix: one native check each in `rules/stmts.rs::invalid_syntax`.
- **YAML: `sudsy format` rejects two actionlint test files the yaml-test-suite's marking does not cover** (`github-actions/actionlint/testdata/err/yaml_syntax_error.yaml`, `.../examples/broken_yaml.yaml`; the GitHub Actions corpus, not the yaml-test-suite): the `yamllint` proof run counts their formatter findings as missing because no corpus marking says the files are invalid. Both are syntax errors for yamllint too, so the likely fix is a marking for them (or the reference of the proof run); decide with the lead.
- **C/C++ `unreachable-code` false positive on lowercase-macro case labels**: a case body that is a lowercase macro call such as `read_sysreg_case(X);` (no `case` keyword visible) reads as a statement after the previous `return`/`break`. Fix: treat a macro-like call statement after a terminator inside a `switch` body as a possible label in shared role precision, or classify via the directive-aware macro pass (Phase 2).
- **Markdown formatter drops a `\_` escape inside strong text** (`runtime-docs/coding-guidelines/clr-code-guide.md`, found in the Prettier parity run; the file is also a `tab-blocks` gap). `- **GCX_MAYBE\_\*(BOOL)**: ...` becomes `- **GCX_MAYBE_\*(BOOL)**: ...` and `**\_ASSERTE.**` becomes `**_ASSERTE.**` (Prettier keeps both). A dropped `\_` can change emphasis parsing, so it is a possible meaning change. The meaning check does not see it: `signature` (`crates/lang-markdown/src/format/signature.rs`) compares prose with `\*` and `\_` undone and the node kinds, so a dropped escape passes unless the node structure differs. This is a gap of the shared meaning check (`signature` runs as the Markdown `extra_check`), not a one-off: any change that only removes a `\_` or `\*` passes it. Fix: keep the escape as written (the shared rewrite that removes it), and make the signature compare the escapes that matter (an `_` or `*` that is a delimiter candidate) or reparse the output and compare its inline structure.
