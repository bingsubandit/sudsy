# Syntax tree, grammars, wire encoding

## Tree
- `rowan` green/red tree (vendored in `third_party/rowan` with a 32-bit `SyntaxKind`; upstream is 16-bit); kinds are `u32`: 8 bits language (0 core, 1 JSON, 2 C#, 3 YAML, ...), 1 token bit, 23 bits index.
- Lossless: printing the tree reproduces the source byte for byte; every conformance test checks it.
- Trivia (whitespace, newlines, comments) are tokens. C# doc comments and directives are structured trivia nodes (tag `#trivia`); disabled `#if` text is one verbatim token.
- `ERROR` nodes hold what could not be parsed; every token stays in the tree. Formatter and rules skip subtrees with errors; files with syntax errors are not formatted.
- Code of another language is parsed beside the host's tree, not inside it ([adding-a-language.md](adding-a-language.md#embedded-languages)).
- A zero-width EOF token takes the leading trivia of the file's tail.

## Trivia attachment (every language)
Trailing trivia: after a token up to and including the end of its line. Leading: everything else before a token. A run between two tokens is split after the first trivia token ending in a line break (`\n`, `\r`, NEL, LS, PS); a run without one is all trailing. `trivia::check_attachment` verifies it (also inside structured trivia).

## Grammars (`grammars/<lang>.grammar`)
- Line-based, ungrammar-like: tokens, nodes with named child fields (`name:Type`, `?`, `*`), comment syntax, `suppress` markers.
- Field types are a kind name or a `#tag`. Tags (`#block`, `#delimited-list`, `#key-value`, `#separator`, `#string`, `#comment`, `#binary-chain`, `#member-chain`, `#restyle`, ...) drive shared shapes, rules and patterns; they double as union types in generated wrappers.
- Bodies match children in order (`core_syntax::ast::assign`); `ShapeChecker` verifies every child lands in a slot (`#opaque` nodes declare no shape and are skipped; `violations` lists every failing node, `provider_api::format_testing::check_corpus_shapes` runs it over a corpus). Generated accessors use the same routine, and so does `Grammar::slot(node, label)`, the generic accessor for a labelled item (shared rules read an entry's `key` and `value` with it; bodies are resolved to ranges of one kind pool when the grammar loads; the hash is computed on first use).
- Tags for shared rules: `#mapping` marks a container of key/value entries (the entries are `#key-value` nodes whose key is the item labelled `key`: JSON `Object`; YAML `BlockMapping`, `FlowMapping`), `#sequence` a list of values (JSON `Array`; YAML `BlockSequence`, `FlowSequence`), `#sections` a file container of sections whose first child, a `#section` header node, has the name token in its `name` slot (INI, EditorConfig `Document`, `Section`). A rule subscribes by tag (`Rule::tags`) and runs for every kind carrying it, in every language that tags its grammar. `Grammar::nodes_with_tag` answers from a table built at load.
- Tags for list items (`shapes::delimited_list`): `#hole` on a node kind or on a separator token kind makes an item that is only its separator (JS `[a, , b]`: the `Elision` node, and a bare `Comma` in a pattern), `#final` on an item kind says that no separator may follow it (a rest element: no trailing comma).
- Roles: a node kind says what it is for cross-language code (layout kits, scope binder, shared rules) with a role tag from the vocabulary below, or `#opaque` when none fits. A kind may carry several roles (a method is a `#declaration` and a `#function`). A role names the fields shared code reads with `Grammar::slot(node, field)`; `field?` is optional, and a required field must be declared in the body, as the item's label or as an alias `label=field:Type` (C# `when_true=then:#expression`; the generated accessor keeps `label`). A grammar opts in with a `roles` line; then `cargo xtask codegen` refuses a node kind with neither a role nor `#opaque` (or with both), and a role whose required fields the body lacks. Tokens are exempt. The table is `core_syntax::roles::ROLES`; adapter-backed grammars (oxc, ruff, ...) opt in the same way and their adapter fills the nodes as the body says.
- Tags for declarations (`shapes::declaration`): `#modifiers` (the node of annotations and keywords in front of a declaration; its leading `#annotation` nodes), `#annotation-arguments` (the parenthesized arguments of an annotation), `#heritage` (a clause after a type's name: `extends`, `implements`, `permits`), `#annotation` also on decorators (JS, Python: `lead_annotations`), `#enum-constant` and `#enum-tail` (the constants and the members after the `;` of an enum body).
- Tags for call arguments (`shapes::call_arguments`): `#huggable` (an object or array that hugs when it has items), `#huggable-always` (a function), `#huggable-function` (a function or lambda, hugging by its body), `#huggable-body` and `#huggable-tail` (body kinds a hugging arrow function may have), `#hug-wrapper` (a cast), `#named-type` (a return type that keeps an arrow function from hugging with an empty body), `#argument` (a node holding one argument expression); `return` and `throw` read `#binary-chain` and `#sequence`.
- Bodies of a grammar that opted in are checked by `ShapeChecker` in every parse test and conformance run (`provider_api::format_testing`): each child of a node lands in an item, separators and `#optional` tokens aside. A kind with no body is not checked, so an `#opaque` kind needs none; a body is written for the kinds that have a role. A tag may hold nodes and tokens (a union such as `#expression` in PHP, where `null` is a bare token): such an item is read with `Grammar::slot`, no typed accessor is generated. A role tag is a node tag, so a token tag of the same name is renamed (`#literal` on Python and Kotlin number tokens became `#number`). Flat operator chains (Python `and`/comparison/chained assignment) put the first operator and operands in the role fields and the rest in an unlabeled `#part*` item. `#conditional` covers the ternary, the `if` expression and the `if` statement (a rule asking for one form checks the kind's `#statement` or `#expression` tag): `condition` and `then` always, `else` when the grammar has an else part; an `elif` or `else-if` clause is a `#conditional` of its own (Python `ElifElseClause`, PHP `IfStatementBodyElseIfClause`), and an `else` clause has no `condition`. Where a language wraps a part in a node of its own (Kotlin `Condition`, `Then`, `Body`; PHP `IfStatementBody`, the body that holds a switch's cases), the field is that wrapper, and shared code looks inside it. `new` stays `#opaque` (C#, PHP).
- Flow tags (read by `unreachable-code` and `no-fallthrough`, [../rules/semantics.md](../rules/semantics.md#flow-family-core_rulesflow_rules)): `#inert` marks a statement that is never reported as unreachable (empty, hoisted, a C# `throw`), `#inert-bare` a declaration that is inert while no declarator has a value (JS), `#goto-target` a labeled statement a `goto` can reach (the code from it on is reachable; C#, C, C++), `#directive` (a preprocessor line among statements: no flow statement; a `switch` holding one may have unseen arms), `#fallthrough` a `switch` whose arms run into the next one (JS, Java, PHP); a grammar with `#break`, `#continue`, `#return` and `#block` gets the family.
- Statement roles: `#loop` (`body`, `condition?`: `while`, `do`, `for`, `foreach`), `#switch` (`cases`, `subject?`) with `#case` arms (`test`, `body`; a C# section has one `test` per label, a Python `case` or PHP `case` one), `#try` (`body`, `catches`, `finally`) with `#catch` (`body`, `parameter?`, `type?`: the caught type; absent in a catch-all), `#return` and `#throw` (`value`, optional), `#expression-statement` (`expression`) and `#empty-statement` (a lone `;`, Python `pass`), `#debugger` (a statement that stops in a debugger), and `#key-value` (`key`, `value?`) for an entry of an object, dictionary or array, or a named argument. Python's `ExprDict` stays `#opaque` (ruff has no node for an entry) and is a `#mapping` whose keys the Python `RuleHooks::flat_keys` reads from the flat children; JS `ObjectExpression`, PHP `Array` and Ruby `Hash` are `#mapping` too, so the shared `no-duplicate-keys` runs on them.
- Marks are tags a kind carries beside its role or `#opaque` (`core_syntax::roles::MARKS`): `#pure` is an expression with no effect of its own, read by `no-useless-expression`; `#with` (Python and JS `with`), `#yield` and `#await` are read by the `simplify` checks (`nested-with`, `jump-outside`). A `rule <id> [level x] [option "value"...]` line gives a shared rule's level and option values in this language (`Grammar::rule_row`).
- Names: a `keys` line (`lowercase`, `decode`, `static`, `strip "<prefix>"`, `alias <field>`, `merge "<text>"`, `accessors "get" "set"`) says how the shared key rules read a key's name; `#key-part` tokens make a key a path, `#number` and `#string` tokens are the scalars of a sequence (`core_rules::names`). `core_syntax::roles` answers by the grammar of the kind's own language: `has(kind, tag)`, `un`/`outer`/`parent` (through `#transparent` nodes, the parentheses), `code_tokens`, `code_text`, `has_own_token`; `core_syntax::strings` decodes quoted strings and integers.
- Adapters of external parsers (`provider_api::adapter`) read `trivia <Token> attribute...`: the text between two tokens that is a `Token` (the parser gives none): `line "p"...` (to the end of the line; `not "p"...` excludes prefixes, `first "p"...` only at the start of the file, `unicode` also ends at U+2028 and U+2029), `block "open" "close"` (`nested`; unclosed runs to the next token), `lines "open" "close"` (starts at the start of a line, ends with the line that starts with the close), `continuation` (`\` that ends a line). `provider_api::adapter::Stream` puts these rows under a hand-written parser that builds its own tree (Java, YAML); `replay_grammar` does it for a parser that reports tokens and nodes (C/C++, HTML). Two language facts are arguments, not rows (one user each): `replay_with(.., continued)` (C/C++ line comments go on over a `\` that ends a line) and `Stream::joining_tabs` (YAML: a tab continues a run of spaces in one `Whitespace` token). Rows are tried in order; text no row matches and that is no whitespace is an `Unknown` token and a parse error. `limits:` in `lang.yaml` (not a grammar row): `stack` (MB; the parse thread's stack, absent: the caller's thread), `bytes` (MB; larger files are not parsed), `depth` (deepest bracket nesting and longest run of the characters of `run`), `tagged: [c, n]` (most nested `(` groups after a name after `c`). A file refused by the limits, or on which the parser panics, is one `Unknown` token and one error. The first node of a grammar is the root, and the tokens `Eof` (or `EndOfFile`), `Unknown`, `Whitespace` and `Newline` are found by name (`Kinds::of`).
- String literals: `string <Token>... attribute...` rows (continued on indented lines) describe one string token kind for `core_syntax::strings::StringSyntax`: `quote "c"...` (delimiters; none: unquoted text), `triple`, `prefix "letters"` and `raw "letters"`, `double` (a doubled delimiter is one), `escape "c"`, `map <"c"|code> <code>...` (escape letter to character), `hex "c" <digits>...`, `octal <digits>`, `named "c"`, `surrogates`, `continuation` (escape before a line break joins lines), `fold` (YAML line folding), `unknown keep|drop|invalid`, `replace <code>` (the character of a malformed hex escape; none: no value), `line` (a line break ends an unclosed non-triple string), `hexrun <n>` (an escape of up to n hex digits and one blank, CSS), `short-hex` (a hex escape may have fewer digits), `nest "#{" "}"` (code inside the string, read by `scan` when asked), `dedent` (a triple-delimited string is a block string whose value is its `dedent`ed lines), `opener "${"` and `resume "}"` (a piece of a template literal ends with the opener instead of a delimiter, and the next one starts with the resume delimiter; an escape of one character of the opener that would make it is no useless escape). Several rows of one token (TOML `'..'` has no escapes) are tried in order by the opening delimiter. `Grammar::string_value(kind, text)` is the decoded value (`None`: invalid escape), `StringSyntax::split` gives prefix, delimiter and content, `encode` writes a value between the row's first delimiter, `unknown_escapes` lists the useless escapes, `scan(src, at, interpolate)` is the end of the string opened at `at` (the CSS, Java, C++ and SQL lexers read their strings with it; SQL has two rows of its `String`, the dialect picks the one with the backslash escape), `escape_len` the length of one escape, `check_escape(src, at, quote)` its length or what is wrong with it (`Bad::Unknown`, `Bad::Hex`: the JSON lexer and the YAML double-quoted scanner report from it), `strings::concat_value` the value of a word of quoted pieces and bare text (a row without delimiters reads the bare text: shell `Word`, read by the Dockerfile `run-command` family), `pieces` the literals written one after the other in a token (Protobuf), `strings::dedent` the lines of a block string (GraphQL); `core_format::literals::string`, `prefixed` and `unescape_quotes` take the escape character (and, for `string`, the `nest` parts that are copied as written) from the row. JSON, TOML, YAML (plain, single and double quoted scalars), Python, JS (strings and template chunks), CSS, Java (strings, text blocks, characters), C++ (strings and characters), C# (regular and verbatim strings, characters), PHP (single and double quoted), SQL, shell words, GraphQL and Protobuf declare rows; their lexers, hooks, value checks, YAML quote changes, Python `prefixed` splitting and `invalid-escape-sequence` (nodes tagged `#string-escapes`: one string piece with one prefix; a row may name the pieces of an interpolated string too) and `no-useless-escape` read them. `regex-call` rows may name `arg <n>` (the pattern is the nth argument) and `delimited` (PHP `'/a+/i'`); a method call's callee text starts with its `object` (`Pattern.compile`).
- Embedded code: `embed <Kind> language "<name>" attribute...` rows say which node or token holds code of another language and how the host's own parts are carved out of it; `container <Node> marker <Token> [prefix "s"]` rows name nodes whose content lines carry a prefix. One finder reads them (`core_syntax::embed_rows::find`, `core_syntax::containers`; attributes in the module headers); the host's provider reports the regions (see [adding-a-language.md](adding-a-language.md)).
- Regex source: `regex <Token> flavor <name> [quote "/"]` says that a token is a regex literal (`/body/flags`), `regex-call flavor <name> [concat "+"] "callee"...` that a call (a `#call` node whose `callee` text is one of the strings) takes the regex as its first argument (`concat`: the operator that joins two strings; a node of `#arguments` is a list whose first child is the argument). The flavor (`ecmascript`, `pcre`, `python`, `java`, `dotnet`, `onigmo`) is a row of `core_rules::regex_source::flavor`. Tags: `#regex` on the node of a literal, `#quoted` on a node whose own `#string` tokens have `string` rows, `#raw-strings` on a node whose last child has no escapes (a JSX attribute, a tagged template). The `regex` rule family reads them ([../rules/semantics.md](../rules/semantics.md#regex-source-core_rulesregex_source)).
- Format strings: `format <flavor> operator "<op>"` (a `#binary` whose left operand is a `#string-literal` and whose operator text is `<op>`: Python `"%s" % x`) and `format <flavor> method "<name>"` (a `#call` whose callee is a `#member-access` of a `#string-literal` with that member: `"{}".format(x)`) say where the arguments of a format string are; the flavor (`percent`, `brace`) is the placeholder syntax of `core_rules::format_strings`. The checks read the tags `#tuple`, `#dict` (the entries of a `#dict` node are nodes followed by a `#key-separator` token; a `#rest` token before one is a `**` spread), `#display` (list, set, dict, comprehension, generator: a value that is never a tuple), `#literal`, `#named-expr`, the `left`, `right`, `operator`, `then`, `else` fields, and for a call the `callee` and `arguments` fields, `#key-value` nodes (`key`) among the arguments and `#rest` for a starred one ([../rules/builtin.md](../rules/builtin.md): `percent-format-*`, `string-dot-format-*`, `printf-string-formatting`, `f-string`).
- Precedence: `precedence <level> <assoc> "op"...` lines (higher level binds tighter; `assoc`: `left`, `right`, `same` (only repeats of one operator flatten: `a * b * c`), `none` (never)) give `Grammar::precedence(text)`; the operator chain kit (`core_format::shapes::binary_chain`) flattens through them, and parentheses decisions read the same table. JS, C# and Java declare them; a chain kind is tagged `#binary-chain` besides `#binary`.
- Operator kinds: the `operator` field of `#binary`, `#unary` and `#assignment` is the operator's token (or, in Kotlin, its `OperationReference` node); `Grammar::operator_kind(text)` says what the text does, from the table below, so a rule asks "is this an equality" in any grammar. A grammar adds or overrides texts with `operators <kind> "text"...` lines (Python `is` is an equality, `//` and `@` arithmetic; PHP `<>`; Kotlin `?:`). The kind is looked up by text and not tagged on token kinds because mago's `Operator` is one token kind for every operator. Where a node holds several operator tokens (Python `not in`, `is not`) the field is the first.

- Decisions every grammar follows:
  - A kind has a role when its body can declare every required field as items of its own; otherwise it is `#opaque`. So `#conditional` is the ternary only and an `if` statement (optional `else`) is `#opaque`; `new` is `#call` (`callee` is the constructed type or expression: JS `NewExpression`, Java `ObjectCreationExpression`; C#'s `ObjectCreationExpression` stays opaque); a statement or expression with no field to read (`return`, `throw`, JSX, TypeScript types) is `#opaque`. A kind with a role needs its whole body, as the shape check reads it; an `#opaque` kind needs none.
  - One field can be several items (`label=field`; labels are unique, fields are not). `Grammar::slot` returns the first child assigned to any of them, in the order of the body. This is the union: a postfix `operator` after the operand and a prefix one before it (`prefix=operator:... operand suffix=operator:...`), and a Java operand that is a node (`left:#expression?`) or a bare token (`left_token=left:#operand?`; tags are uniform, so one item cannot take both). When a required token of the same kind follows, the token item goes first: Java `#type-token? #type? name:Identifier` (a node return type must not leave `name` to a token item).
  - A field that is a list in the language but has no list node in the parser's tree is a repeated item (`arguments:#expression*` of a JS call, whose `(`, commas and `)` are children of the call); `slot` returns the first, a layout walks the children between the delimiters.
  - Union tags a body names: `#expression`, `#statement`, `#member` (class, interface and enum members), `#pattern`, `#parameter` (nodes); `#identifier` (Identifier and Keyword: oxc has reserved words as names, `as const`, `yield`), `#operator` (every token that can be an operator: JS `Operator`, `Keyword` for `in` and `typeof`, `LAngle`, `RAngle`; Java `Operator`, `Lt`, `Gt`, `Assign`), `#operand` and `#type-token` (Java tokens that stand for an expression or a type) are tokens.
  - JS: `IdentifierReference` is `#reference` and `BindingIdentifier` `#declaration` (the binding site); the named constructs (function, class, method, property, variable declarator, enum, interface) are `#declaration` too, with the name as a child `BindingIdentifier` or key (`name:#expression`), not a token. `#scope` kinds: program, function, arrow, block, class, static block, `for` statements, `catch`, `switch`, module block, interface. Parenthesized assignment targets and `for` heads keep their `(` `)` as children of the statement or expression. The adapter sorts oxc's nodes by start so that a function's `this` parameter and decorators before `export` are in source order.
  - Java: identifiers and literals are bare tokens in expressions (the grammar has no node for them), so Java has no `#reference` or `#literal` node yet; roles sit on the `*Core` nodes of type declarations (`ClassDeclarationCore` holds the name and the body, `ClassDeclaration` is a wrapper with the modifiers) and on `TypeOrStaticImportDeclaration`; `MethodInvocation` is `#call` with `callee` the method name and `object` the receiver (a member access and a call in one node).
  - Parts the parser does not emit are optional items, and no adapter wraps them: the implicit receiver of a Java `f()` (`object`), a JS `new Foo` without `(`. Node kinds with a role / `#opaque`: JS 44 / 147, Java 37 / 112.

- `grammars/csharp.grammar` follows Roslyn's field lists (321 node kinds, 252 token kinds); hand-maintained. Types are also expressions (every `#type` kind carries `#expression`).
- The typed wrappers (`generated` in each language crate) and the grammar registry (`core_syntax::grammars`) are generated by build scripts (`build/lang-crate.rs`, `core-syntax/build.rs`) from `grammars/*.grammar` into `OUT_DIR`, so a grammar file is the whole registration. `cargo xtask codegen` writes the worker's kind table (`workers/csharp/Sudsy.Worker/Generated/CsharpGrammar.g.cs`), `schemas/sudsy.schema.json`, the docs' tables and the editor files; `xtask/full/tests/codegen_is_fresh.rs` fails on stale output.
- `language <name> <id> ["Display"]`: the display name (`C#`) is what generated language lists print; it defaults to the name.

## Wire encoding (`core-syntax/src/wire.rs`)
Per file, never per node; token text is not sent (the receiver has the source).
- `version: u32`, `kinds`: `bin` of little-endian u32 (version 2), `values`: `bin` of LEB128 varints (token: UTF-8 width; node: child count), inside the MessagePack message.
- Node widths are derived from children. Whether an element is a token is a bit of its kind.
- Why flat arrays in `bin`: smallest encode+decode overhead (4.8% of Roslyn parse on CoreLib) and no second container format.
- The real cost is not the encoding but Roslyn's red-node materialization during the mapping walk (see [numbers](../performance/numbers.md)).
- Decoding rejects trees nested deeper than `MAX_DEPTH` (2048 levels) with `WireError::TooDeep`: rowan drops a green tree recursively, once per level, and a debug build on a 2 MB stack survives about 3000 levels. The file then fails to parse instead of overflowing the stack.
- Hand-written parsers (`core_syntax::parse`): `Lexer` (text, position, tokens that tile the file, errors), `Parser` (tokens with the trivia each real token owns by the attachment rule, cursor, tree builder, depth guard `enter`/`leave`, one diagnostic per error site, `ERROR` nodes), `ParseError` and `Parsed`. `Pratt` and `climb` parse binary operators by the levels of the grammar's `precedence` lines (the host reads the operator at its token and wraps the tree). JSON and CSS are on `Lexer` and `Parser`; Java is on `Stream` and `climb`; YAML on `Stream`; C/C++ and HTML on `replay_grammar`. SQL keeps its own flat parser and lexer (dialect-switched scanning, node spans replayed by `replay`).
