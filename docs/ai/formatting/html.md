# HTML (`lang-html`)

## Parser
One hand-written, lossless parser reads all four languages (`crates/lang-html/src/parser/`: `mod.rs` the shared HTML reading, `tags.rs` the implied end tags and void elements, `svelte.rs` and `angular.rs` the braces and blocks of those modes). It makes tokens and nodes in a single pass and `adapter::replay` builds the tree from them, so the tree is lossless and the parser never panics (elements nest to 256 levels, deeper ones are siblings and an error). The tree shape is `grammars/html.grammar`; its nodes are `#opaque` (no roles yet). Errors do not stop the parse: a raw `<` in HTML and Svelte text (a `>` or an `&` that starts no entity is text; the rules `no-raw-gt` and `no-ambiguous-ampersand` report them), an end tag that closes nothing, an unclosed comment, element, block or ICU expression are findings and the rest of the file is still a tree.

- An `Element` is its start tag (`StartTag`, also for `<a/>` and `<br>`: its closing `>` or `/>` is one kind of token), its content and its `EndTag`. Void elements (`<br>`, `<img>`) and elements closed by an implied end tag (`<p>`, `<li>`) have no `EndTag`; the tree is the source as written, not the browser's repaired tree. `script`, `style`, `textarea` and `title` are `Element`s too.
- Text, entities (`&amp;`), CDATA sections and the content of `script`, `style`, `textarea` and `title` are one `Chunk` each, with a `Text`, `Entity`, `CData` or `RawText` token inside. Whitespace between nodes is trivia; comments are trivia.
- The attributes of a tag are `#key-value` entries of a `#mapping`: an `AttrName`, and when written an `=` and an `AttrValue` (quotes included).
- `Doctype` is `<!`, the keyword (`DoctypeKw`, any case), `DoctypeBody` and `>`. An end tag that closes no open element is a `StrayEndTag`.

Files: `.html`, `.htm` (`*.component.html` is Angular, below).

`dialect: template` (HTML only, default `auto`: plain HTML) reads `{{ ... }}` of Go templates (Hugo) as an `Interpolation` the printer keeps as written (`core_syntax::template_actions` with the words of `go_template.rs`; the dialect reaches the parser through `SourceFile::language_version`). An action among the attributes is one attribute, kept as written; a quoted value is re-quoted by the quotes outside its actions. Safe by refusal, with a parse error (the file is not formatted): a block (`if`, `range`, `with`, `define`, `block` up to `end`; `else` inside) that does not open and close among the children of one element. `dialect: template-open` drops that refusal: a block may span elements and the file is laid out by the tree of its markup (an element a block opens stays open, as the tree says); no end tag the source lacks is written where an action could end the element elsewhere (any element of a file that has `{{`, and an element that runs to the end of a file without one; a file without actions gets its omitted `</p>`, `</li>` as in HTML), and the safety check compares the start and end tags of such a file token by token (`MarkupFormatter::extra_check`: the generic check skips `EndTag`), so an added or dropped end tag is refused. The html-eslint preset sets it. A `}}` ends an action, also in a quoted value, whose quotes may then hold `"` (the printer re-quotes it with `'`). On the html-eslint corpus (Bootstrap's Hugo site) 1 of 259 files is refused: an action in an end tag name (`</h{{ .Level }}>`).

## Vue
`.vue` files are the `vue` language (`crates/lang-html/src/dialect.rs`): the HTML tree read in `Mode::Vue` (entities stay in the text, `{{ }}` is an `Interpolation` of `{{`, a `Chunk` and `}}`, a directive name is several `AttrName` tokens: `:`, the name, `.`, a modifier; void elements need their exact lowercase name; root elements other than `template`, `script` and `style` are raw custom blocks unless the file is an HTML page), the config section `vue` on top of `html`, and the formatter above with these additions:
- `content_newline_with_attributes` and `indent_expression_operands` lay out like eslint-plugin-vue (`singleline-html-element-content-newline` with its default `ignores`: `INLINE` in `format/model.rs`; `html-indent`: embedded expressions get `EmbedMode::ExpressionIndented`, the JS binary chain then indents its operands). With `single_attribute_per_line` and `whitespace_sensitivity: ignore` on the Vue corpus they clear the 360 `singleline-html-element-content-newline` findings and 383 of 527 `html-indent` ones; 144 remain: object and ternary continuation lines inside an expression (Prettier's `? ` alignment and nested object indent differ from the rule's offsets).
- Element names and attribute names keep their case. Root elements are blocks; a root block other than `template`, `script` and `style` (and a `template` with a `lang` other than `html`) is a custom block: formatted as JSON, YAML, GraphQL, Markdown, JS or TS by its `lang` (or `type="application/json"`), else kept.
- The content of a root `<script>` and `<style>` starts at the margin unless `indent_script_and_style` (below). TypeScript expressions when a root script has `lang="ts"`.
- `{{ expression }}` is formatted as an expression (`{{ a + b }}`, the expression on lines of its own when too wide, a lone interpolation hugs its tags); an expression that does not parse is kept (its lines without the indentation they share).
- Directives (`:a`, `.a`, `@a`, `#a`, `v-*`, `slot-scope`) are formatted as expressions: an object, array or function hugs the quotes, a string or template literal stays on the line, anything else goes on lines of its own when too wide. `@a` and `v-on` are statements when the value is not an expression. `v-for` keeps its loop variables (joined, parenthesized when several) and formats the collection.
- Not done: Vue filters, `v-for` / `v-slot` / `generic` values as parameter lists, `<template lang="pug">` content, `<script setup="...">` values.

| Option | Values | Default | Description |
|---|---|---|---|
| `indent_script_and_style` | bool | `false` | Indent the content of the root `<script>` and `<style>` blocks of a `.vue` file by one level. |

The other options are HTML's, from the `html` section (`vue:` overrides).

## Formatting
Prettier's printer-html is the reference (`format/model.rs` builds the nodes and the whitespace flags, `format/print.rs` lays them out); the defaults equal Prettier's.
- **Whitespace model:** whitespace between inline content is significant. Each node knows whether blanks before and after it are significant (from the CSS display of its neighbors and parent, Prettier's table of element defaults, `<!-- display: block -->` before an element overrides it) and whether there were blanks in the source. Where blanks are significant and absent, the closing `>` of the previous tag or the `<name` of the next one moves onto the neighboring line (`<a>x</a\n><b>y</b>`), so lines can break without adding rendered whitespace. `whitespace_sensitivity: ignore` makes every element a block, `strict` every element inline.
- **Elements:** children go on their own lines when they do not fit, block children always; `html`, `head`, `ul`, `ol`, `select` and table parts always break their children; one blank line between children is kept. Void elements and `<a/>` print as `<br />`; implied end tags are written (`<li>x<li>y` becomes two `<li>...</li>`); element names of known HTML elements and attribute names of known HTML attributes are lowercased (the word lists are the `[case]` rows of `format.rules`).
- **Text:** words are filled to `line_width`. `pre`, `textarea` and `listing` keep their text exactly (a `pre` that holds elements is kept as written); `script` and `style` content is dedented and re-indented, not formatted.
- **Attributes:** values are double-quoted unless they hold more `"` than `'`; `class` values have their blanks collapsed; they fill the line or, when the tag is too wide, go one per line (`single_attribute_per_line`) with the `>` on its own line or at the end of the last attribute (`bracket_same_line`).
- **Comments:** stay where they are; a comment with blanks around it is on a line of its own. `<!-- prettier-ignore -->` and `<!-- sudsy-ignore -->` keep the next node as written.
- **Safety check:** the formatter rewrites the case of tag and attribute names and the doctype, the quotes of attribute values, the blanks of text and the form of the closing `>`; those tokens are `#restyle` and `HtmlFormatter::value` compares them without these changes. An end tag is `#transparent`: written or removed freely.
- **Embedded code** (`format/print/embed.rs`): the content of `<script>` (JS by `type` or `lang`; TS for `lang="ts"` or `application/x-typescript`; JSON for `*json`, `*importmap`, `speculationrules`; Markdown, HTML; other types are kept) and `<style>` (CSS, SCSS or Less by `lang`) is dedented, formatted by that language's formatter for the width left after the indentation, and indented again. Lines inside a template literal keep their indentation (they are not dedented). Attribute values: `style` is a declaration list (`style="color: red; margin: 0"`, one declaration per line with a final `;` when it does not fit), event handlers (`on*`) an expression, else statements (statements that format to one expression, such as `f(x => y)`, are one: no `;`); `srcset` of `img` and `source` is a list of candidates (aligned when broken); `allow` of `iframe` a list of directives. Code that does not parse, or whose language is not installed, stays as written; `embedded_language_formatting: off` keeps all as written. The host reaches the other formatters through `FormatCtx::embed` ([../architecture/adding-a-language.md](../architecture/adding-a-language.md)). The safety check leaves these values to the formatter of their language.
- **Front matter:** in HTML, Vue and Svelte files, `---` (YAML) or `+++` (TOML) alone on the first line, closed by the same line, is formatted by the YAML or TOML formatter and followed by one blank line; one with a language word (`---mycustomparser`) or that does not parse is kept.
- **Not done yet:** IE conditional comments as markup, and keeping text, an inline element and text written without blanks together on one line (see the parity gaps).

## Lint
The rules are named and ordered after html-validate (`docs/ai/parity/html-validate.yaml`; `docs/ai/parity/htmlhint.yaml` and `html-eslint.yaml` map onto the same rules where they agree), run on the tree above: shared rules on the tags (`no-duplicate-keys` on attributes, compared in lowercase through `HtmlHooks`), pattern files in `crates/lang-html/rules/` for what a node, its text and its neighbors decide (case, quoting, spacing, self-closing and void tags, doctype, implicit end tags, `button` and `input` types, empty `title` and headings, ARIA roles, `valid-id`, `meta-refresh`, `require-sri`, `long-title`, `area-alt`, `svg-focusable`, `text-content`, `aria-label-misuse`, `prefer-native-element`), and two Rust families:
- `meta` (`checks.rs`): checks against the element metadata `data/elements.txt`, generated by `data/generate.mjs` from html-validate's element table (names, entities, void and deprecated elements, boolean, empty-allowed, deprecated and required attributes, the values an attribute is limited to): `no-unknown-elements`, `deprecated`, `no-deprecated-attr`, `element-required-attributes`, `attribute-boolean-style`, `attribute-empty-style`, `attribute-allowed-values` (listed values, and the metadata's patterns as regexes, for each token of a list attribute; `{id}` and `id={expr}` are not read), `element-name`, `use-baseline` (an element, attribute or value that not all browsers support at the `available` level, `widely` by default: the table `data/baseline.txt`, generated by `data/generate-baseline.mjs` (run by hand like the other generators; the pin is the `version` of `docs/ai/parity/html-eslint.yaml`, the html-eslint of the corpus run) from the support data bundled in @html-eslint/core 0.68.0, looked up by the shared `core_rules::feature_support`; names the table lacks and custom elements are not reported; a `sms:` link is not checked);
- content model (`content.rs`, `access.rs`, data `data/model.txt` generated by `data/generate-model.mjs`): the shared `core_rules::content_model` (rows: categories, permitted content, excluded descendants, order, required children, implied elements) and `core_rules::markup_checks` (the words of HTML) over the shared element tree `core_rules::markup`: `element-permitted-content`, `element-permitted-order`, `element-permitted-occurrences`, `element-required-content`, `link-text` (WCAG H30), `form-submit` (H32), `header-scope` (H63, non-strict), `hidden-focusable`, `img-alt` (options `skip_hidden`, `other_elements`, `name_counts`), `click-events-have-key-events`, `interactive-supports-focus`, `mouse-events-have-key-events`, `label-has-control`, `empty-content` (a link, button or heading with nothing in it) and `no-autofocus`. `data/spelling.txt` says how each dialect writes a bound attribute or an event (Angular `[x]`, `[attr.x]`, `bind-x`, `(x)`, `on-x`; Vue and plain HTML `:x`, `v-bind:x`, `@x`, `v-on:x` with modifiers after `.`; Svelte `on:x` with modifiers after `|`; the longest file-name suffix picks the rows): `Markup` reads each attribute as `base` name and `bind` kind, so a check asks for `alt` or the event `click` once (`v-for-key` reads its key through the same rows). `data/accessibility.txt` holds the categories of those checks (labelable elements, widget elements, roles that are not widgets, elements that need content), each with its source. `Markup` reads the elements inside a block (`@if (x) { ... }`, Svelte `{#if}`, an ICU case) as children of the element around it. The pattern rules `prefer-control-flow` (`*ngIf`, `*ngFor`, `[ngSwitch]`) and `table-scope` (`scope` outside `<th>`) belong to the Angular preset. A `<script>` or `<style>` after `</body>` opens an implied `<head>` the way html-validate's `implicitOpen` does, which is the source of the three findings of such a file. Elements the rows do not name (custom elements) are not judged.
- document rules (`document.rs`): `no-duplicate-id`, `no-duplicate-class`, `no-multiple-main`, `heading-level`, `no-missing-references`, `no-redundant-for`, `no-conditional-comment`, `input-missing-label`, `multiple-labeled-controls`, `unique-landmark`, `map-dup-name`, `unrecognized-char-ref`;
- `names` family targets (`patterns.rs`, mode `pattern`): `id-pattern`, `class-pattern`, `name-pattern`, `attr-pattern`, each with a `pattern` option (a regex) whose default is html-validate's (kebab-case ids and classes, camelCase names, letters digits `-` and `:` for attribute names).
- Vue and Svelte template rules (pattern rules and the `template` family over the shared tree, so each runs on every dialect; fixtures under `tests/rules/{html,vue,svelte}`, run with the dialect's own provider): eslint-plugin-vue's essential rules (`valid-v-*` including the `v-if` / `v-else-if` / `v-else` chain; `no-deprecated-*`, `v-for-key`, `no-use-v-if-with-v-for`, `no-lone-template`, `no-textarea-mustache`, `require-component-is`, `no-child-content`, `no-use-v-else-with-v-for`, `no-v-text-v-html-on-component`, `no-dupe-v-else-if`), its shorthand rules (`v-bind-style`, `v-on-style`, `v-slot-style`, with fixes), `attribute-hyphenation` and `v-on-event-hyphenation`, all on; `no-v-html`, `html-self-closing` (its defaults) and `attributes-order` (its default order) are off; eslint-plugin-svelte's `require-each-key`, `no-at-html-tags`, `no-at-debug-tags`, `no-dupe-on-directives`, `no-dupe-use-directives`, `no-dupe-style-properties`, `no-raw-special-elements`, `no-unknown-style-directive-property` (the CSS language's property table), `no-useless-children-snippet` and `no-useless-mustaches` (on), and off by default `shorthand-attribute`, `shorthand-directive` (with fixes), `spaced-html-comment`, `no-nested-style-tag`, `no-bind-value-on-checkable-inputs`, `no-target-blank` (also the Vue and html-eslint rule; it wants `rel="noopener noreferrer"`) and `no-v-text`. Rules that need script analysis or a comparison of expressions (`no-dupe-else-if-blocks`, `valid-each-key`) are not implemented; `no-dupe-v-else-if` compares the conditions as text. Parity: [../development/parity.md](../development/parity.md#eslint-plugin-vue-and-eslint-plugin-svelte). The preset `html/eslint-plugin-vue-recommended` also sets the layout options `single_attribute_per_line: true` and `whitespace_sensitivity: ignore` (what `max-attributes-per-line`, `html-indent` and `singleline-html-element-content-newline` ask for); `ignore` lays out inline elements as blocks, which can change the spaces a browser renders; the default stays `css`. Rules that clash with plain HTML (`slot`, `is`, a bare `<template>`, `<head>`) only run on `.vue` or `.svelte` files (`only` param). Catalogs: `docs/ai/parity/eslint-plugin-vue.yaml`, `eslint-plugin-svelte.yaml`. `@click`, `v-on`, `#slot`, `on:` and `use:` may repeat on one element and are not checked by `no-duplicate-keys`.

The parser already reports a stray end tag, a raw `<` in text and a self-closed `<script>` as `syntax-error`, which is the equivalent of html-validate's `close-order`, `close-attr`, `no-raw-characters` (a lone `&` is the rule `no-ambiguous-ampersand`, which html-validate-recommended turns on) and `script-element`. Presets: `html/html-validate-standard` and `html/html-validate-recommended` ([presets.md](presets.md)). Which rules run without a config: [../config/sudsy-yaml.md](../config/sudsy-yaml.md#zero-config).

## Svelte
`.svelte` files are the `svelte` language (`Mode::Svelte`: `{expression}` and `{@html x}` are a `Mustache`, `{#if}` / `{:else}` / `{/if}` are `BlockTag`s inside a `Block` node, `{name}` is an attribute shorthand; braces are matched over strings and comments). The formatter follows prettier-plugin-svelte:
- Case is kept. The root is sorted as the plugin does by default: `<svelte:options>`, scripts, markup, styles (a comment moves with the node below it), one blank line between; `<script>` and `<style>` content is indented (`indent_script_and_style`, default `true`).
- A block `{#if}` / `{#each}` / `{#await}` / `{#key}` / `{#snippet}` is a `Block` of branches: each tag on its own line with its content indented below; the condition of `if`, `else if` and `key` is formatted as an expression.
- `{expression}` is formatted (`{@html x}`, `{@const a = b}` hug the braces); attribute values `name={expression}` hug like Vue's, `name={name}` becomes `{name}`, `bind:name={name}` `bind:name`, and `name="{expr}"` `name={expr}`.
- The root is rewritten before formatting when it needs sorting (`rewrite_source`), as are the attribute shorthands. Not done: blocks and tags written without blanks stay inline, `prettier-ignore-start`/`-end`, mustache tags inside quoted attribute values are not broken.

| Option | Values | Default | Description |
|---|---|---|---|
| `indent_script_and_style` | bool | `true` | Indent the content of the root `<script>` and `<style>` blocks of a `.svelte` file by one level. |

## Angular
`*.component.html` files are the `angular` language (`crates/lang-html/src/angular.rs`, `dialect.rs`). `Mode::Angular` of the shared parser reads what Angular's compiler and Prettier's angular-html-parser read: control flow blocks, `@let`, ICU messages, `{{ }}` closed outside string literals, case-sensitive names, `/>` closing any element, bracketed attribute names (`[class.[&>svg]:w-4]`), CDATA sections as text (`NgBlock` of a `BlockHead` and its content, `NgLet`, `Icu` of `IcuCase`s; `AtName` and `NgCode` tokens, the code of a block head or ICU being compared by position only). An incomplete block, `@let` or ICU expression, a stray `}` and an end tag that closes nothing are findings, and the rest of the file is still a tree. Only the name `*.component.html` selects the mode: any other file name is plain HTML, and a file-to-language mapping in `sudsy.yaml` does not exist yet.
- The formatter is HTML's (Prettier's printer-html, which also prints Angular) plus `format/print/angular.rs`: `@if (a) {` ... `} @else {` (sibling blocks that continue each other share the line of the closing brace, `@for` keeps `let ...` as written, a `;` after the last parameter is dropped), `@let a = expr;`, ICU as `{n, plural, =0 {...}}`, `i18n` attributes collapsed.
- Expressions go through the TypeScript formatter (`lang-js`) as in Vue: `[x]` / `bind-x` expressions, `(x)` / `on-x` statements (`a(); b = 1`), `{{ }}` in text and in attribute values (an attribute value with `{{ }}` keeps its text and breaks inside the braces), `*dir` microsyntax (`let h of hs; trackBy: tb`, `a | async as v; else tpl`) read by `format/print/microsyntax.rs` (Angular's `parseTemplateBindings`). Pipes are no TypeScript: `pipes.rs` splits a lone `|` from the expression (arguments at `:`, ternaries kept), formats the parts and prints `x | date: "short" : tz`; a parenthesized group holding a pipe is masked while the rest is formatted, and Angular words that are reserved in JavaScript are renamed around the call. An expression that does not parse (an unparenthesized arrow function, a pipe inside a call argument) is kept as written.
- The `html` rules and the `template` family run on the tree (the Vue-only ones have `only: vue`);
- Angular template rules (the `template` family with `only: component.html`, text checks in `ng_checks.rs` over bindings, interpolations and block heads; fixtures under `tests/rules/angular`): @angular-eslint's `banana-in-box`, `eqeqeq` and `no-negated-async`, and `require-for-track` (`@for` without `track`, a compiler error); `no-implicit-button-type` and `no-inline-style` also cover its `button-has-type` and `no-inline-styles`. ## html-eslint

`scripts/parity.sh coverage html-eslint` formats the corpus with the `html-eslint-recommended` preset and lints it again; layout findings that remain count as missing, except those pinned per finding in `tests/parity/html-eslint/differences.yaml` where the tool is wrong:

<!-- generated:differences:html-eslint -->

- `action-attribute`: the tool counts the words of a `{{ if }}` action among the attributes of a tag as attributes; Sudsy keeps the action as one attribute
- `action-text`: the tool reads the text of a `{{ }}` action as markup (a tag or comment inside a string) and its words as elements; the action is one piece of text and stays as written
- `end-tag-in-base`: the tool reports a start tag whose end tag is in another file of the project (the `<body>` of a `{{ define }}` that `baseof.html` closes); each file of a template project is a part of the page
- `front-matter`: the tool reads the front matter between the two `---` lines as text to indent; it is data of the page generator and stays as written
- `hugo-template-tokens`: the tool reads the text of a Hugo template inside a tag (`{{`, `}}`, `end`, `with`, `.Level`, `(eq`) as attribute, class or element names; the file is a template, not HTML, and no real attribute is repeated outside a template action
- `textarea-value`: the tool indents the text of a `<textarea>` (its ignore list names `pre` and `xmp` only); the text is the value of the field, so reindenting changes it
