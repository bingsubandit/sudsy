# Python (`lang-python`)

## Parser
[`ruff_python_parser`](https://github.com/astral-sh/ruff) 0.0.14 (MIT) with `ruff_python_ast` and `ruff_text_size`, pinned to the exact version in the root `Cargo.toml` (the version Pyrefly pins; dependabot ignores the `ruff_*` crates). The crates are 0.0.x and change weekly, so a bump is a deliberate change of `grammars/python.grammar` and `crates/lang-python/src/adapter.rs`.

`adapter.rs` builds our tree (the shape of `lang-js`'s) from three inputs:
- the lexer's tokens, one token kind per ruff `TokenKind` (names as ruff's: `Name`, `Lpar`, `If`, `String`, `FStringMiddle`, ...). Comments are `Comment` trivia; logical and non-logical newlines, indents and dedents are `Newline` and `Whitespace` trivia, and a backslash that ends a line is `Continuation`;
- the AST's node spans, from one `SourceOrderVisitor` walk: each AST node is a node of the tree, named as in ruff (`StmtFunctionDef`, `ExprCall`, `Arguments`, `Parameters`, ...), `ModModule` is the root. A node with no token (a name error recovery adds) is an empty node;
- the text between two tokens, split into trivia tokens and attached by the shared trivia rule. A byte-order mark is leading trivia; text that is none of these is an `Unknown` token and an error.

ruff's expression ranges exclude parentheses, so the adapter makes a `Parenthesized` node (tagged `#transparent`) around each parenthesized expression or pattern, one per pair, nested for `((x))`. The parentheses of a call or of a class's bases belong to `Arguments` and make none.

Errors: ruff recovers from syntax errors and its errors cascade, so a file reports the first error of each statement (code `syntax-error`), and the version errors of the option `target_version` (`lazy import` before 3.15) are syntax errors. A file with errors is reported, not formatted.

## Formatting
The output is `ruff format` 0.17.4's (Black's style) under its defaults; `scripts/parity.sh format ruff` compares the two on the pinned corpus (black's test cases, ruff's formatter fixtures, six Black-formatted projects; numbers in [../performance/numbers.md](../performance/numbers.md)) and `tests/parity/ruff/differences.yaml` ratchets each group. Code: `crates/lang-python/src/format/` (`stmt` blocks, blank lines and comments, `paren` where parentheses stand, `expr`/`list`/`op` the expressions, `literal` and `docstring` strings and numbers).
- Statements: blank lines as ruff (two around top-level `def` and `class`, one nested, one after imports and after a module or class docstring, up to two or one kept elsewhere, none at the start of a block except in a function body and before a nested `def`); a `...` body stays on the header line; `a; b` is two lines; `class A():` loses its parentheses.
- Brackets: calls, collections, parameters, subscripts and `with` items split at their brackets, the items on one line when they fit there and one per line (a comma after the last) when they do not; a trailing comma in the source keeps the list expanded (`magic_trailing_comma`); imports in parentheses are always one per line.
- Parentheses: redundant ones go (`x = (1)`, `for (a, b) in c`, `return (a + b)`) and come back when the expression does not fit (`x = (\n    a + b\n)`); an expression that ends in a bracket splits there instead (`x = f(a) + g(\n    b\n)`), a call that fits in parentheses after `=` is parenthesized when the line up to its first bracket does not fit. Calls chained with two or more `.attr` after a call or subscript break before each of them. Operators break before the operator; `a**b` of simple operands has no spaces; slices get spaces around `:` when an operand is not simple.
- Strings: quotes follow `quote_style` (the other quote when that needs fewer escapes; raw and triple-quoted strings keep theirs unless safe), prefixes are lowercase except `R`, `u` goes; numbers are lowercase with upper-case hex digits; implicit concatenations of plain strings are joined when the line holds them, else one part per line. Docstrings: the first statement of a module, class or function body; quotes `"""`, indentation of the lines after the first re-indented to the block, trailing blanks removed.
- Comments: `#comment` becomes `# comment` (not `#!`, `#:`, `##`), two spaces before a trailing comment (its text counts for the width unless it is a tool pragma: `noqa`, `type:`, `pylint:`, ...), comments at the end of a block stay in it. A second comment that lands on the line of another goes on its own line, a comment after an operator stays with the operand before it, `# fmt: off` / `# fmt: on` and a trailing `# fmt: skip` (simple statements, after their `;` too) and `sudsy-ignore`, `sudsy-ignore-start`, `sudsy-ignore-end` keep statements as written.
- The text is prepared before formatting (comments, `class A():`, see `PythonFormatter::rewrite_source`); the safety check follows it: a pair of parentheses is not compared (`Lpar`, `Rpar` are optional and `Parenthesized` is transparent), a string expression is compared by prefix and body (so joining implicit concatenations and changing quotes pass), a docstring without its indentation.
- Not done: code in docstrings (`docstring-code-format`), quotes inside f-string replacement fields, comments in unusual places (kept, but not always where ruff puts them: between `lambda` and its body, after an operator or a `|`, after a bracket before a first item on its own line), `# fmt: skip` on compound headers and `# fmt: off` inside brackets, preview style.

Python code in Markdown fences (`python`, `py`) is formatted and linted with the Python options and rules ([markdown.md](markdown.md)).

### Scope layer
The rules of `F4`, `F8` and `E74` (unused and undefined names, redefinitions, imports, `__all__`, star imports, shadowed imports, ambiguous names) read the scope model (`src/semantic.rs`): the shared binder of `core-semantics::scopes` run over the lossless tree with Python's table (`scope.rows`, with `globals/python.txt`), a list of rows by node kind. The node kinds are ruff's AST names, so a row says which kinds open scopes (module, function, lambda, class, comprehension), declare names, read them or write them, and how a target, an annotation or a `global` / `nonlocal` statement passes its role on to its children. Python needs four things of the table that the shared options carry: a name written in a target declares itself (`implicit`), `global` and `nonlocal` redirect a declaration to the module or an enclosing scope (`redirect`), a class scope is invisible to the functions nested in it (`hidden`), and the strings of a type position are kept for the layer to parse as annotations (`text`). There is no second parse of the file and no parser dependency outside `adapter.rs`; the model is built by the first rule that runs on a file and kept for the others (one per thread), and a file with syntax errors gets none of these diagnostics (the parser's own `syntax-error` is reported).

Resolution is by name up the scope chain and does not depend on order, like hoisting; what depends on order is read off positions by the shared ordered rules (`core_rules::scope_rules::ordered`, [../rules/semantics.md](../rules/semantics.md#ordered-rules)): each declaration has the position where it takes effect (the end of its statement, the end of the iterable of a `for`), a read finds the last declaration that has taken effect, a rebinding inherits what read the old binding, only the last declaration of a name is reported as unused, and two declarations redefine each other only when they are consecutive and in the same branch (an `if` / `elif` / `else` clause, a `try` part, a handler, a `with` or `match` case). Function bodies, lambdas and annotations that are quoted, under `from __future__ import annotations` or (3.14) lazy run after the module: a read from there finds the last binding. The names in a quoted annotation are read from the string by the shared binder (identifiers outside nested quotes and not behind a `.`; a string that cannot be one expression gives none); `Literal[...]` and the strings after the first argument of `Annotated` are left alone, and `forward.rs` parses the others with the Python grammar for `forward-annotation-syntax-error`. The shared code also describes an import (its form and the qualified name it stands for, which the rules of other families use to find `typing.Optional` or `os.error` through aliases); the rules `unused-import`, `unused-variable` (also `unused-annotation` and `unused-unpacked-variable`, rows with `mode`), `undefined-variable` (and `undefined-local-with-import-star-usage`), `undefined-export`, `use-before-define` (F823), `redeclared-variable` (F811) and `shadowed-variable` (F402 and PLR1704) are `family: scope` rows of `rules/checks.yaml`; Python keeps the table, `globals/python.txt` (the builtins), the tags of `python.grammar` and its `Ordered` facts (`__all__`, `__future__`, `NameError`, `typing.overload`, `Literal`, `Annotated`, the ignored `__traceback*` names) in `src/semantic.rs`, and `rules/scope.rs` holds the star-import checks and the quoted-annotation syntax check. The other rules of `src/rules/` read the shape of nodes through the accessors of `tree.rs` (`stmts.rs`: layout, comparisons, jumps and `__future__`; `lints.rs`; `format.rs`: `%` and `str.format` strings, escapes, dict keys). `invalid-syntax` reports a duplicate parameter, a repeated keyword argument, `nonlocal` at module level and `await` outside an async function; the other semantic syntax errors of ruff's parser are named gaps.

`scripts/parity.sh ruff` compares the findings with ruff's (`--select` the mapped rules, `--target-version py314`, noqa comments ignored; the run fetches the corpus) on the rule fixtures and the real-world files of the corpus ([../development/parity.md](../development/parity.md)): 1047 findings, 0 mismatches. A differential run over CPython's `Lib`, black's and ruff's test files (`ruff check` against `sudsy lint`, not part of the gate) differs in a handful of lines, listed in [../bugs.md](../bugs.md).
